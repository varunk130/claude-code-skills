# AI Search Visibility Optimizer

> When buyers ask an assistant instead of a search box, the shortlist is written before they visit your site - this skill gets you onto it.

## What this skill is

A repeatable audit-and-fix workflow for how a brand, product, or category appears inside answers generated by Large Language Model (LLM) assistants and AI search surfaces. It measures share of answer on a fixed, intent-weighted query set, traces which third-party sources the engines cite, and converts the gaps into specific content, entity, and off-site actions. It treats AI visibility as a measurable channel with a baseline and a re-test cadence, not a one-time optimization trick.

## What it solves

- Teams optimizing for blue-link rankings while AI answers recommend competitors for the same intent
- Brand descriptions in AI answers that are outdated, wrong, or borrowed from a competitor's framing
- One-off "we asked ChatGPT and we showed up" anecdotes with no repeatable measurement
- Content that ranks but is never cited because it lacks extractable facts, comparisons, or clear entity signals
- Ignoring the third-party sources (review sites, forums, listicles, documentation) that engines actually cite

## When to invoke

- Quarterly visibility baseline for a product category across AI assistants
- After noticing branded or category demand shifting from search to assistants
- Before a launch or rebrand, to make sure engines describe the new positioning correctly
- When sales hears "the AI told me to look at Competitor A"
- When planning a content roadmap that must earn citations, not only clicks

## Phase 1: Design the query set

Build 30-60 prompts that a real buyer would type, grouped by intent. Fix the set and version it so later runs are comparable.

| Intent tier | Example prompt pattern | Weight |
|-------------|------------------------|-------:|
| Category discovery | "Best tools for <job> for a <segment> team" | 3 |
| Comparison | "<Brand> vs <Competitor A> for <use case>" | 3 |
| Problem-led | "How do I <solve pain> without <constraint>" | 2 |
| Alternatives | "Alternatives to <Competitor A>" | 2 |
| Branded fact | "What does <Brand> cost / integrate with / do" | 1 |

Rules: include 3-5 persona or segment variants, phrase prompts conversationally, and record engine, model or mode, date, location, and whether browsing or search grounding was on.

## Phase 2: Run and score share of answer

Run each prompt at least 3 times per engine (answers are non-deterministic). Score each response:

| Score | Meaning |
|------:|---------|
| 0 | Brand absent |
| 1 | Mentioned in passing or in a long list (position 5+) |
| 2 | Listed in top 3-4 with neutral description |
| 3 | Recommended first or as the best fit for the stated need |

Add a sentiment and accuracy flag per mention: accurate, outdated, wrong, or negative.

```
Share of answer (SoA) = sum(score x intent weight) / (max score 3 x sum(intent weight)) across runs
Mention rate = responses with brand / total responses
```

Report SoA per engine, per intent tier, and versus the top 3 competitors on the same set.

## Phase 3: Citation-source gap analysis

For engines that show sources, log every cited Uniform Resource Locator (URL) and classify it.

| Source type | Examples | Your presence | Competitor presence | Gap action |
|-------------|----------|---------------|---------------------|------------|
| Owned | Product pages, docs, pricing, blog | | | Restructure for extraction |
| Review and directory | Software review sites, marketplaces | | | Profile completion, review drive |
| Community | Forums, Q&A sites, developer threads | | | Authentic participation |
| Editorial | Listicles, analyst notes, newsletters | | | Outreach with data assets |
| Reference | Wikis, knowledge bases, open datasets | | | Neutral factual entries where notable |

Rank sources by citation frequency. The top 10 cited domains are the real distribution channel - prioritize gaps there before writing anything new.

## Phase 4: Entity and fact consistency check

Engines assemble answers from entity facts. Audit whether the same facts appear consistently everywhere:

| Fact | Canonical value | Site | Docs | Review profiles | Social bios | Structured data |
|------|-----------------|------|------|-----------------|-------------|-----------------|
| Category label | | | | | | |
| One-line description | | | | | | |
| Pricing model and starting price | | | | | | |
| Primary integrations | | | | | | |
| Target segment | | | | | | |

Any cell that conflicts is a likely source of wrong or hedged answers. Add Organization, Product, and FAQ structured data (schema.org markup) where appropriate.

## Phase 5: Content fixes for extractability

Rewrite or create pages so an engine can lift a correct answer:
- **Answer-first blocks**: a 40-80 word direct answer under each question-style heading
- **Comparison pages** with honest tables (criteria, where each option fits, where you do not)
- **Facts pages**: pricing, limits, security, integrations, stated plainly with dates
- **Original data**: benchmarks, surveys, or usage statistics others will cite
- **Specific nouns**: name the job, segment, and integration rather than generic claims

Score each priority page 1-5 on: direct answer present, verifiable facts, freshness date, comparison coverage, and crawlability (no critical content behind scripts or logins).

## Phase 6: Prioritize and re-test

| Fix | Intent tier affected | Expected SoA lift (L/M/H) | Effort (L/M/H) | Owner | Re-test date |
|-----|----------------------|---------------------------|----------------|-------|--------------|

Re-run the identical query set every 4-8 weeks. Attribute movement cautiously: engines update models and indexes independently of your changes, so track a control set of prompts you did not target.

## Output

- Versioned query set with intent weights and run conditions
- Share-of-answer scorecard per engine, intent tier, and competitor
- Accuracy log of wrong or outdated statements about the brand
- Citation-source map with top 10 cited domains and gap actions
- Entity-consistency table with conflicts flagged
- Prioritized fix backlog with owners and a re-test calendar

## Operating rules

**Always**
- Run every prompt multiple times per engine and report averages, not single screenshots
- Record engine, mode, date, and grounding settings for every run
- Benchmark against named competitors on the identical query set
- Fix factual inconsistencies across owned and third-party profiles before producing new content
- Keep a control set of untargeted prompts to separate your impact from engine drift

**Never**
- Promise rankings or guaranteed inclusion in AI answers
- Publish fake reviews, astroturfed forum posts, or hidden text aimed at crawlers
- Treat a single engine as the whole channel
- Change the query set between runs and then compare scores
- Optimize branded-fact prompts while ignoring category discovery, where buying decisions start
